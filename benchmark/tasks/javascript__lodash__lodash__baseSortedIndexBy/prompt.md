# Functional specification: `baseSortedIndexBy(array, value, iteratee, retHighest)` in `lodash.js`

## 1. Component overview

Internal helper of lodash 4.17.14 behind `_.sortedIndexBy` and
`_.sortedLastIndexBy` (and, for non-number search values or very long arrays,
behind `_.sortedIndex`, `_.sortedLastIndex`, `_.sortedIndexOf` and
`_.sortedLastIndexOf`, which pass `identity` as the iteratee). Given an array
that is already sorted by the ranking produced by `iteratee`, it returns the
index at which `value` should be inserted to keep the array sorted: the
**lowest** such index, or the **highest** one when `retHighest` is truthy. The
ordering it assumes is exactly the ascending order produced by `_.sortBy`, which
places "special" values after all ordinary values.

## 2. Functional requirements

1. Compute the rank key of `value` by calling `iteratee(value)` exactly once,
   and the rank key of a probed element `array[i]` by calling `iteratee(array[i])`
   (one argument only). Elements are only examined through such probes.
2. Search by repeated halving (binary search) over the index range
   `[0, length)`, where `length` is `array.length`, or `0` when `array` is `null`
   or `undefined`. The iteratee is therefore called `1 + p` times, where `p`, the
   number of probes, is about `log2(length)`: e.g. for a sparse array whose
   `length` is `2^31` or `2^32 - 1`, the iteratee runs 32 or 33 times in total.
   Probe positions are the midpoint of the current range rounded down, so index
   arithmetic must stay exact for lengths up to `2^32 - 1` (do not use 32-bit
   integer tricks that overflow).
3. Ordering classes, ascending: (a) *ordinary* keys (everything not listed
   below: numbers, strings, objects, booleans, ...), compared among themselves
   with JavaScript's `<` / `<=` operators; then (b) symbols; then (c) `null`;
   then (d) `undefined`; then (e) `NaN` (any key not equal to itself).
4. With `retHighest` falsy, the result is the number of leading elements whose
   key ranks strictly before `value`'s key; with `retHighest` truthy, the number
   of leading elements whose key ranks before or equal to it. Concretely, a probed
   key `c` counts as "before" the search key `v` when:
   - `v` is `NaN`: `c` is not `NaN`, or `retHighest` is truthy;
   - `v` is `undefined`: `c` is not `NaN`, and (`retHighest` or `c !== undefined`);
   - `v` is `null`: `c` is neither `NaN` nor `undefined`, and (`retHighest` or `c !== null`);
   - `v` is a symbol: `c` is not `NaN`/`undefined`/`null`, and (`retHighest` or `c` is not a symbol);
   - `v` is ordinary: if `c` is `null` or a symbol it is never before; otherwise
     it is before when `c < v` (or `c <= v` with `retHighest`). Note that
     `undefined`/`NaN` keys then compare false and so are never before an
     ordinary `v`.
5. Return the resulting index, but never more than `4294967294`
   (`MAX_ARRAY_INDEX`, the largest valid array index).

## 3. Input specification

- `array`: an array (possibly sparse, possibly with a `length` up to
  `2^32 - 1`) sorted ascending by the rules above, or `null`/`undefined`.
- `value`: any value to locate.
- `iteratee`: a function of one argument returning the rank key (callers convert
  property shorthands such as `'x'` into such a function beforehand).
- `retHighest`: optional boolean; truthy for the "last index" variants.

## 4. Output specification

A non-negative integer index in `[0, min(length, 4294967294)]`.

Examples (identity iteratee `I`; `lo` = `retHighest` falsy, `hi` = truthy):

- `[30, 50]`, value 30 / 40 / 50 -> lo: 0, 1, 1; hi: 1, 1, 2
- `['a', 'c']`, value `'a'` / `'b'` / `'c'` -> lo: 0, 1, 1; hi: 1, 1, 2
- `null` or `undefined` array with any value (1, `undefined`, `NaN`) -> 0
- `E = [1, '2', {}, s1, s2, null, undefined, NaN, NaN]` (`s1`, `s2`, `s3` symbols):
  value 3 -> lo 2, hi 2; `s3` -> lo 3, hi 5; `null` -> lo 5, hi 6;
  `undefined` -> lo 6, hi 7; `NaN` -> lo 7, hi 9
- `[null, null]`: value `null` -> lo 0, hi 2; value 1 or `'a'` -> 0
- `[s1, s2]`: value `s3` -> lo 0, hi 2; value 1 or `'a'` -> 0
- `[{ x: 30 }, { x: 50 }]`, value `{ x: 40 }`, iteratee `o => o.x` -> 1 (both variants)
- an empty array with `length = 2^32 - 1` (all holes, so every key is `undefined`):
  value `4294967295` -> 0 (lo and hi); value `NaN` -> 4294967294 (lo and hi);
  value `undefined` -> lo 0, hi 4294967294
- iteratee called with exactly one argument, first with the search value
  (e.g. `[40]` for value 40).

## 5. Edge cases and constraints

- Must not mutate `array`; holes read as `undefined`.
- Must call `iteratee` only once for `value` and once per probe (no linear scan,
  no pre-mapping of the array).
- Mixed-type ordinary keys are compared with the plain relational operators,
  including their coercions (e.g. `{} < 3` is false).
- Runs in O(log length) iteratee calls.
