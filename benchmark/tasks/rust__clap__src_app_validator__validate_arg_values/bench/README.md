Workload: one multi-valued option per line with CaseInsensitive / EmptyValues / StrictUtf8 (app) / validator /
validator_os settings, an optional possible-values list, and the matched values. S holds the possible-value, case,
empty-value, UTF-8 and validator cases of the test suite (passing and failing); M/L hold 500-5000 and 5000-50000 values
per argument generated by the driver (xorshift) from 1-30 possible values, ~30% of them ending in one offending value.
Invocation: `driver.rs` is appended to `src/app/validator.rs` of a container-local copy (`/tmp/w`, `/w` never
modified) as `mod tc_bench`; apps, args, MatchedArg and ArgMatcher are built before timing, then
`Validator::new(&mut app.p).validate_arg_values(&arg, &ma, &matcher)` is called. `check` hashes Ok / error kind,
message and info (FNV-1a 64).
