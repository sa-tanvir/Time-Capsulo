# Functional specification: `func genMan(cmd *cobra.Command, header *GenManHeader) []byte`

## 1. Component overview

Package `doc` (`github.com/spf13/cobra/doc`) generates man pages for cobra
command trees. `GenMan(cmd, header, w)` first completes the header
(`fillHeader`), then calls `genMan(cmd, header)` to build the page **in
Markdown** (the dialect understood by `go-md2man`), and finally converts it to
roff. `genMan` therefore returns the complete Markdown source of the man page
for one command: title block, name, synopsis, description, options, example,
"see also" links and a history line.

## 2. Functional requirements

1. **Initialisation (side effects on `cmd`).** First call
   `cmd.InitDefaultHelpCmd()` and `cmd.InitDefaultHelpFlag()` so that the
   automatic `help` sub-command (when `cmd` has sub-commands) and the
   `--help/-h` flag exist; the help flag therefore appears in the options.
2. Let `D` be `cmd.CommandPath()` with every space replaced by `-`
   (e.g. `root echo` → `root-echo`).
3. Output, in this order, into one buffer:
   1. the preamble written by `manPreamble(buf, header, cmd, D)`;
   2. the option sections written by `manPrintOptions(buf, cmd)`;
   3. if `cmd.Example` is non-empty: the line `# EXAMPLE`, then a fenced code
      block: a line with three backticks, the example text verbatim, a newline,
      a line with three backticks, i.e. ```` "# EXAMPLE\n```\n" + Example + "\n```\n" ````;
   4. if `hasSeeAlso(cmd)` is true: the line `# SEE ALSO`, then a single line
      containing the links joined by `", "` (comma + space) and terminated by
      `"\n"`. The links are, in order:
      - if `cmd` has a parent: `**P(S)**`, where `P` is the parent's
        `CommandPath()` with spaces replaced by `-` and `S` is
        `header.Section`;
      - then, for each child of `cmd` **sorted by name**, skipping children that
        are not available (`!IsAvailableCommand()`, which also excludes the
        `help` command) or that are additional help topics:
        `**D-<child name>(S)**`.
   5. unless `cmd.DisableAutoGenTag` is true: the line `# HISTORY`, then the
      line `<date> Auto generated by spf13/cobra`, where `<date>` is
      `*header.Date` formatted with the Go layout `"2-Jan-2006"`
      (e.g. `7-Jun-2019`), each line ending with `"\n"`.
4. **Inherited "no auto-gen tag".** When `cmd` has a parent and any ancestor
   (parent, grand-parent, … root) has `DisableAutoGenTag == true`, set
   `cmd.DisableAutoGenTag = true` before deciding about the history section,
   so no `# HISTORY` section is written. `cmd.DisableAutoGenTag` is never
   reset to false.
5. The children of `cmd` end up sorted by name in place (the child slice
   returned by `cmd.Commands()` is sorted).
6. Return the bytes of the buffer.

Example. Given root `root` with persistent flag `rootflag`, its child
`echo` (`Use: "echo [string to echo]"`, `Short: "Echo anything to the screen"`,
`Example: "Just run cobra-test echo"`, runnable children `times` and
`echosub` and a deprecated child) and header `Section: "2"`,
`Date: 2019-06-07`, `genMan(echo, header)` contains, after the preamble and
options:

~~~~
# EXAMPLE
```
Just run cobra-test echo
```
# SEE ALSO
**root(2)**, **root-echo-echosub(2)**, **root-echo-times(2)**
# HISTORY
7-Jun-2019 Auto generated by spf13/cobra
~~~~

(the deprecated child and `help` are not listed). For root `root` with
children `aaa` (hidden), `bbb`, `ccc` and section `1` the see-also line is
`**root-bbb(1)**, **root-ccc(1)**`.

## 3. Input specification

- `cmd`: non-nil `*cobra.Command` anywhere in a tree.
- `header`: non-nil, already completed by `fillHeader` (`Date` non-nil,
  `Section` non-empty, private `date` set).

## 4. Output specification

- A `[]byte` holding the Markdown text described above. Every section ends
  with a newline.

## 5. Edge cases and constraints

- Root command without available children: no `# SEE ALSO` section.
- Sub-command without children: see-also line contains only the parent link.
- No example → no `# EXAMPLE` section.
- `header` is not modified. `cmd` may be modified as described (help command,
  help flag, child order, `DisableAutoGenTag`). Calling twice gives the same
  result.

## Header type (same file)

```go
// GenManHeader is a lot like the .TH header at the start of man pages. These
// include the title, section, date, source, and manual.
type GenManHeader struct {
	Title   string
	Section string
	Date    *time.Time
	date    string // Date pre-formatted as "Jan 2006"; filled in by fillHeader
	Source  string
	Manual  string
}
```

`genMan` is called by `GenMan(cmd, header, w)` only **after** `fillHeader(header, cmd.CommandPath())`
has completed the header: `Title`, `Section`, `Date` (non-nil), `date` and `Source` are all set.
`GenMan` then converts the Markdown returned by `genMan` to roff with `md2man.Render`.

## What the same-file helpers write

- `manPreamble(buf, header, cmd, dashedName)` writes the title block
  (`% TITLE(SECTION)date`, `% source`, `% manual`), then `# NAME` with
  `<dashedName> \- <cmd.Short>`, `# SYNOPSIS` with `**<cmd.UseLine()>**`, and
  `# DESCRIPTION` with `cmd.Long` (or `cmd.Short` if `Long` is empty), followed by a blank line.
- `manPrintOptions(buf, cmd)` writes `# OPTIONS` (the command's non-inherited flags) and
  `# OPTIONS INHERITED FROM PARENT COMMANDS` (inherited flags), each only when the set has
  visible flags; hidden and deprecated flags are skipped.
