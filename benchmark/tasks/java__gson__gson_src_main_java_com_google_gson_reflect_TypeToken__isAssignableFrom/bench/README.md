Each workload line: from-type name, to-type name (a ParameterizedType), optional initial type-variable map (name=type,...). Type names refer to a fixed catalogue built in the driver: generic fields (List<String>, Map<String,Integer>, ...), a small user hierarchy (A<T>, B<U> extends A<List<U>>, C extends B<String>, E2<K,V>), raw classes, a type variable, a wildcard, null, and a hierarchy chain D0..D40 (D_k<T> extends D_(k+1)<T> implements J_k<T>; J_k<T> extends J_(k-1)<T>) used for queries such as D_k:String -> J_x:Integer. S: all catalogue pairs plus a few chains of depth <=4; M: chains of depth 6-12; L: chains of depth 20-40 (false answers walk the whole hierarchy).
The driver (package com.google.gson.reflect, compiled against gson/target/classes into /tmp/tcb; /w is never modified) calls the private static method via reflection with a fresh HashMap per call; in check mode it digests the boolean result (or exception) and the final contents of the map. In time mode maps are created outside the timed region.
